# Caveworkers company production release



## No-new-billing release path



## Service topology

| Service | Exposure | Responsibility | Secrets it may receive |
|---|---|---|---|
| `caveworkers` | Public HTTPS Cloud Run service | Authentication, company tenancy, Firestore records, queue, approval records, Razorpay owner checkout, SSE workroom, token minting, and output redaction | Application, Firebase, payment, connector, model, and capability-signing secrets required by Caveworkers only |


## Employee execution contract

| Employee | Private runtime skills | Initially usable bridge intents | Explicitly unavailable without a later adapter and approval design |
|---|---|---|---|
| Data Analyst | KPI analysis, SQL analysis, anomaly detection, business reporting | Read bounded task context and memory; persist a reviewable draft artifact | Database writes, messages, payment activity, external publishing |
| Cybersecurity Analyst | Defensive log, dependency, configuration, and incident analysis | Read bounded task context and memory; persist a defensive draft artifact | Scanning, exploitation, identity changes, credential handling, production changes |
| Full Stack Backend Developer | Repository analysis, debugging, API design, migration planning, code review | Read bounded task context and memory; persist an implementation draft | Repository writes, merge, migration, deployment, secret changes |
| Software QA/Automation Engineer | Test strategy, regression analysis, API testing, defect analysis | Read bounded task context and memory; persist a test-plan draft | Personal-browser control, shared-environment mutation, production testing; sandbox requests need manager approval |

Every bridge call requires a short-lived, single-use capability generated by Caveworkers. The token binds the company, employee, task, exact intent, expiry, and nonce. A static MCP bearer is transport authentication only; it does not authorize tenant data. Capability tokens are redacted from outputs and cannot be reused.

## Operator release sequence


Next, create the `caveworkers` Artifact Registry repository, submit the three Cloud Build definitions, and deploy the public service with [`deploy-caveworkers.sh`](../deploy-caveworkers.sh). Set the actual public HTTPS address as both `PUBLIC_APP_URL` and the appropriate `ALLOWED_ORIGINS` entry. Configure that host in Firebase Authentication, the Google OAuth redirect client, and Razorpay’s webhook configuration. Deploy Firestore rules from `firebase.json` before allowing customer sign-in.



The first live runtime test must use a non-production company test tenant and the Data Analyst only. Submit a bounded analysis request that reads task context and creates a draft artifact. Verify the tenant-scoped artifact, task record, audit record, and absence of a payment or external-action event. Then exercise cancellation, a deliberately failed capability, a replayed nonce, and a manager approval pause. Do not enable a second employee until every expected result is visible in the correct tenant’s records and no data appears in another tenant.


## Company acceptance gate

| Area | Required evidence before inviting customers |
|---|---|
| Identity and tenancy | Firebase Google sign-in, logout, session revocation, company membership isolation, CSRF rejection, and cross-tenant API denial |
| Payments | Live-mode Razorpay order and signature validation in the intended account, valid webhook delivery, duplicate-webhook handling, invalid-signature rejection, reconciliation owner, and refund process |
| Durability | Firestore backups, documented restore exercise, retention/deletion export check, and queue recovery check |
| Employee workrooms | One task for each of the four employees with an approved plan, isolated history and memory, and an auditable result or safe fallback |
| Operations | `/api/health` monitoring, error monitoring, alert routing, named incident owner, support inbox, scheduler tick, structured logs, and release rollback owner |


## Scale and change-management boundary

The controlled initial production configuration is company-ready for a managed low-volume launch with one public worker instance. It is not a claim that the current process-local realtime layer is horizontally scalable. Before raising `max-instances` above one, move rate limiting, employee presence, SSE event fan-out, and remaining cache state to shared managed services; add queue lease metrics, dead-letter operations, and retry backoff observability. Release these changes through a staging environment, not directly against customer tenants.
